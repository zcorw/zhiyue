# 文章状态筛选 · 2026-11-16

用户纠正“知声需要草稿”指文章状态筛选，并确认增加“已发布 / 草稿 / 全部”切换，默认保持已发布。

## 范围与行为

- 列表页新增状态按钮，点击或镜腿选中后单击按“已发布 → 草稿 → 全部”循环。电脑预览使用下拉选择。每次应用启动、换账号默认已发布；同一列表会话返回、隐藏后恢复保留所选状态。
- 切换状态回到第一页并取消旧请求；迟到结果不能覆盖新状态。
- 草稿沿用知声规则：没有当前发布版本，包括已撤稿的文章。读取最近已保存的标题、正文、分类和最后成功音频，不读取浏览器中未保存的编辑。
- 已发布读取发布快照，包括已冻结的标题、正文、分类和音频。已发布后尚未重新发布的编辑不作为另一篇草稿出现在列表中。
- “全部”按当前发布或草稿状态列出，每篇文章一次。按发布时间或草稿保存时间倒序，文章 ID 打破同时间排序；跨分页遇并发内容变化可重新加载。
- 知声分类、关键词、总数和分页均在所选状态范围内。后端检索支持显式状态，模型不决定访问范围；此前知阅语音检索的未提交改动未纳入本次独立提交。草稿行显示“草稿”和保存日期，正文标题标记草稿。

## 接口和模块

`GET /v1/zhiyue/read/articles`、`GET /read/articles/:id` 支持 `status=published|draft|all`，省略为 published。`POST /read/search` 的 JSON 可加 status，返回 filters.status，后续分页复用。

列表/详情增加 status、updatedAt；草稿 publishedAt 为 null。详情 contentVersion 表示正文版本，releaseId 为发布版本或草稿音频 ID（无音频时为草稿版本句柄），客户端按来源申请音频票。`POST /read/drafts/:id/audio-ticket` 接收精确 audioId；票据绑定账号、设备、文章和音频版本，每次读取重新检查。在音频已替换、文章处于发布状态或已删除、设备已撤销时拒绝旧草稿票。

知阅 `aiui/lib/article-status.js` 管理状态和日期适配，列表页管理交互与取消，`zhisheng.js` 管理状态传递、响应验证及分来源音频缓存；阅读页保留来源和内容版本。知声独立 `zhiyue-content.ts` 实现设备本人草稿和混合读取，普通 CMS 发布阅读令牌不扩展到草稿。未新增依赖或付费调用。

知声 OpenAPI 1.10.0 共 83 个操作，新增 `1794873600000-zhiyue-draft-media.cjs` 迁移。在正常发布流程执行迁移和知声更新后，使用 [状态筛选源码包](../artifacts/zhiyue-article-status-20261116.zip) 或当前 aiui 目录重新打包；旧服务不能提供草稿读取。
