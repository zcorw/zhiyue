# 同一设备重复绑定与重启后掉绑修复

## 用户报告与判断边界

2026-11-16，用户提供知声「我的设备绑定」截图：多条「知阅眼镜」记录都显示绑定后一天到期。用户补充，眼镜来自最近一次项目 `aiui/` 源码打包，重新打开时直接显示未绑定。

源码核查确认两个问题：连接页把短期访问凭据的 `expiresAt` 标为设备绑定的「到期时间」；配对没有稳定设备身份，每次新配对会分配新记录。当前源码已经有刷新凭据与自动续期，不能把截图中的一天期限直接当作长期授权确实只有一天的证据。

重启后直接未绑定提示本地凭据恢复异常。本轮在模拟运行时复现了「运行时 localStorage 丢失、宿主存储保留」的相同症状，并补充恢复路径；尚未读取真实眼镜的存储或日志，不能据此宣称已证实该固件的 localStorage 生命周期有问题。官方文档描述 localStorage 具有持久化和智能体隔离能力，也提供 wx 同步存储接口，具体固件上的跨启动行为仍需验收。[AIUI 存储文档](https://github.com/yodaos-project/AIUI/blob/main/documentation/3-api/storage-api.md)

## 本地实现

- 知阅新增存储适配：能力存在时优先使用 `wx.getStorageSync` / `wx.setStorageSync`，兼容迁移旧 localStorage 值；没有原生能力时保留原实现。写入读回校验，失败不视为可靠保存。注销保留删除标记，避免从旧副本恢复已移除的凭据。
- 每个知声来源及应用安装持久保存一个随机 UUID，通过 `X-Zhiyue-Device-Id` 传递。该标识不是授权凭据，不替代手机确认和访问/刷新凭据；正常重启、续期、解绑或重新配对不改变它。
- 知声在设备申请与绑定中保存设备标识，数据库约束同一账号和标识最多一条记录。手机重新批准同一安装后复用逻辑绑定，替换旧凭据和媒体票，不重复占用设备配额。
- 有效历史绑定可在升级或续期时登记安装标识，保留原账号与绑定编号；标识冲突不能覆盖另一绑定或突破账号边界。
- 知声连接页显示「长期绑定 · 自动续期」「等待眼镜确认连接」或旧授权状态；长期授权不再显示访问凭据的一天期限为解绑时间。后端未返回新字段时显示待更新确认，不擅自宣称长期有效。
- OpenAPI 更新为 1.9.0，生成类型与契约指纹同步。数据库迁移、新回归及真实 HTTP 客户端夹具已写入知声本地源码，CI 加入设备身份专项。

修改保留现有只读权限、密码修改撤销、普通网页退出保留及账号隔离。私人正文和音频仍不持久化为离线库。

## 已知边界

这里的设备身份是同一智能体/应用安装中的稳定身份。清空所有应用数据、重装或导入为另一个智能体可能产生新标识；未接入未验证的硬件序列号 API。旧记录没有设备标识，不能仅凭相同名称判断属于同一副眼镜；本轮未自动批量合并、撤销或清理线上旧记录。

## 更新与真机验收

知声需先按正常发布流程应用本次代码和数据库迁移，再更新眼镜包。本次没有发布或部署。眼镜源码包为 [`zhiyue-device-binding-fix-20261116.zip`](../artifacts/zhiyue-device-binding-fix-20261116.zip)，其中包含最新 `aiui/`；此前 v1/v2 包为历史快照。

在 AIUI Studio Global 导入新源码、打包，并通过 Hi Rokid 更新同一智能体的眼镜资源。仅更新电脑预览或 Studio 模拟器不等同眼镜已更新。已有凭据若早已丢失，需要先配对一次；本轮不会猜测或还原已经丢失的账号凭据。

验收依次检查：绑定后退出并重新打开；设备标识及逻辑绑定不变；隔天打开自动续期；停用后联网恢复；同一安装重新配对记录数不增加；网页撤销或改密码后旧授权不可继续；普通网页退出不影响眼镜。记录固件、Hi Rokid 版本、智能体标识和资源包版本。未通过这些步骤前，不将本地回归写成真机已修复。
