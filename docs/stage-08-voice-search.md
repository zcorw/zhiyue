## OpenAI 边界

只传识别后的短文本，不传音频、正文、分类表、设备凭据或账号资料。模型只生成检索意图、关键词和从用户话语提取的分类名称；服务端在当前可读发布分类与历史名称中映射 id，再经 CMS 当前权限读取。API 使用 `store: false`，应用代码不记录检索文本，不承诺第三方零保留。密钥只在知声服务端配置。最初拟发送分类元数据的写入被自动审批拒绝；已改为仅发送用户授权的识别文本。

基础解析处理“查找文章……”“查看……分类”“全部文章”等明确口令；OpenAI 用于自然表达的意图和关键词提取。未配置、拒答、超时或无效输出回退基础解析，并标明来源。语义解析不等同音频重新识别，也不保证修复所有同音错字。

## 验收

- 镜腿可选择语音入口；用户主动开始，停止等待最终文字，取消/隐藏后释放识别会话，不自动重开。
- 分类检索、多篇结果和后续分页保持同一筛选；唯一文章进入正文，返回保留检索。
- 无结果、权限拒绝、无语音、网络失败可恢复；绑定变化不保留原账号检索。
- 后端拒绝未授权读取，分类仅来自当前可读发布；模型输出不能扩大权限。

官方依据：[Rokid SpeechRecognition](https://open.rokid.com/aiui/api/ai/speech-recognition?lang=en-US&version=0.19.0)、[OpenAI 结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 启用与操作

1. 本次已获用户授权的配套改动在 `D:/Workspace/github/tts-workbench`：只读路由、语义解析模块、服务端配置及相关测试/契约。已在功能分支整合包含确认/自动续期协议的主线并推送 `4c96b64`；PR #12 尚未合并，部署仍另行执行。
2. 知声部署环境同时设置 `ZHIYUE_OPENAI_API_KEY` 和 `ZHIYUE_OPENAI_MODEL` 才启用语义增强。模型需支持 Responses API 的严格 JSON Schema 输出；模型由运营配置，不在眼镜工程中固定。不配置时基础检索仍可运行。实际费用取决于选定模型和用量。
3. 请求仅发向固定 `https://api.openai.com/v1/responses`，禁止重定向；6 秒独立截止时间覆盖响应体，失败回退基础检索。设备 JSON 请求仍为 10 秒截止时间。搜索接口每 IP 每分钟最多 12 次，不自动重发语义请求。
4. 更新知声服务后，再在 AIUI Studio Global 导入本项目 `aiui/`，确认 `RECORD_AUDIO` 权限并生成 AIX。该步骤与真机安装尚未执行。
5. 镜腿在首篇文章向上先选账号，再向上选语音；演示模式首篇向上直接选语音。单击开始，说“查看科技分类”或“查找文章第一班电车之前”；单击结束，返回取消。检索后返回键恢复全部文章。正文返回保留筛选。

`POST /v1/zhiyue/read/search`：设备 Bearer + JSON `{ "text": "查看科技分类" }`（1–200 字符）。响应含 `items/total/offset/limit`（首屏固定 12）、`kind`（article/category/all）、`filters`（q 最长 120 字符、category 为精确 UUID/uncategorized/空）、`label`、`noMatch` 和 `resolvedBy`（openai/local/fallback）。后续 `GET /read/articles?limit=12&offset=12&q=...&category=...` 复用 filters，无需再次语义解析。未知分类以空结果返回，客户端恢复时不将空 filters 当作全部文章。
